# Agent 职责分离

> 多 Agent 协作的核心不是"拆几个 Agent"，而是**按「生成」和「决策」拆**。生成归生成，决策归决策。

## 核心原则

一个系统里多个 Agent 协作时，最容易犯的错是**职责重叠**——两个 Agent 干同一件事，或者一个 Agent 越界干了另一个的活。

最清晰的拆法，是区分两种本质不同的智能：

| 层级 | 干什么 | 本质 | 例子 |
|---|---|---|---|
| **生成层** | 产出候选/草稿 | 发散、穷举、广度 | 故事师提选题、统计挖数据 |
| **决策层** | 评判/排序/拍板 | 收敛、判断、取舍 | 制片排选题、审核师定 pass/revise |

## 为什么生成和决策要分开

1. **它们是两种智能**：生成要"多"，决策要"准"。让一个 Agent 既生成又决策，它会两头都做不好。
2. **决策需要全局视野**：生成者只看到自己产出的东西，决策者能横向比较所有候选。
3. **可替换性**：生成层可以换（统计、LLM、人工都行），决策层独立不耦合。

## VibeCut 的真实案例：制片 Agent

选题推荐最初被想成"一个功能"，但拆开后是两层三角色：

```
生成层：统计挖掘(数据向候选) + 故事师(叙事向候选)
   ↓
决策层：制片 Agent（评判流量/差异化/钩子/匹配 → 排序 → 首推 + 理由）
```

- 统计能算出"EP22 冲突密度 100%"，但不能判断"值不值得做"
- 故事师能提出"苏明成救赎"，但不能排序"它和 EP21 窒息哪个更该做"
- **制片**不生成，只消费候选做决策——它自己生成就等于"第二个故事师"

详见 `docs/tech/TOPIC_RECOMMENDATION.md`。

## 一个真实的坑：证据公平性

多源候选喂给决策 Agent 时，**证据强度必须对等**，否则决策 Agent 会系统性偏向"有硬数据"的一方。

制片 Agent 第一次跑，把"数据向选题（冲突密度 100%）"当强证据、把"叙事向选题（hook 一句话）"当弱证据，导致叙事向选题全被挤出 Top 15。修复：prompt 里明确"两种证据性质不同但价值等同"。

## 反例：什么时候不该拆

- **单一职责就够**：如果只有一种候选来源、没有比较需求，一个 Agent 生成 + 简单排序即可，不必硬拆决策层。
- **决策很简单**：如果排序规则是确定性的（按分数），用程序排序就行，不用 LLM 决策 Agent。

判断标准：**决策需要"判断"（语义、权衡、取舍）时，才需要独立的决策 Agent；纯机械排序用程序。**
