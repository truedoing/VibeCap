# 视觉语言模型 (VLM)

> 能"看图说话"的模型：VibeCut 视频画面理解的核心

## 是什么

VLM（Vision-Language Model）是**同时看图和读字**的模型：输入图片（或多帧视频），输出文字描述、回答关于画面的问题。

```
纯 LLM:    文字 → 文字
VLM:       图片 + 文字 → 文字
```

VibeCut 用的是 MiMo 的 `mimo-v2.5`（多模态），把视频抽帧 + 场景信息发给它，让它描述画面内容。

## 与纯文本 LLM 的本质区别

| 维度 | 纯 LLM | VLM |
|------|--------|-----|
| 输入 | 只有 token | 图片 token + 文本 token |
| 理解 | 语言世界 | 视觉世界（人物/场景/动作/光线） |
| 盲区 | 看不到画面 | 能描述"谁在做什么、什么氛围" |
| 局限 | 幻觉知识 | 人脸识别会认错、角色泛化（把配角认成主角） |

**关键认知：** VLM 的"认人"（人脸识别）不可靠（VibeCut 实测 ~29% 错误），但"描述画面"（动作/氛围/光线/构图）可靠。**所以人物归属不交给 VLM，画面理解才交给它。**

## VLM 能做什么（在视频处理里）

- **画面描述**：`车内，苏明玉闭眼倚靠座椅，苏明成眉头紧皱，二人沉浸在压抑的氛围中`
- **结构化视觉元数据**：景别 / 构图 / 机位 / 情绪 / 强度 / 光线 / 动作
- **场景情绪判断**：`emotional_tone: 压抑沉郁, intensity: 4`

这些输出喂给下游：
- **分镜匹配**：解说词 → 场景画面的语义匹配
- **时间轴预览**：每个镜头显示 VLM 详情，人工核对
- **索引增强**：画面描述进 BGE 索引，支持"按画面搜"（如搜"打斗场景"）

## VibeCut 的 VLM 管线（三层推理）

```
字幕 (subtitle_result.json)
  → DeepSeek 场记Agent → scene_map (人物+地点+事件+情绪)
  → 字幕关键词锚定 → 精准时间边界
  → VLM 画面分析 (scene_map 的 mood 锚定, 场景 1/3+2/3 位置采帧)
```

**三层各管一件事：**
1. **场记 Agent（DeepSeek）**：读字幕 + 剧情 → 人物/地点/事件/情绪（**人物权威**）
2. **字幕关键词锚定**：时间边界
3. **VLM**：只描述画面（景别/构图/情绪/动作），**不负责认人**

### 为什么 VLM 不负责认人

VLM 人脸识别把配角认成主角（EP21 车里柳青被认成苏明成）。如果让 VLM 输出人物，错误会污染整个分镜匹配。所以：

```
人物的权威 = scene_map.characters（字幕 + LLM 推的，0% 错误）
VLM 的职责 = visual_summary + 视觉元数据（画面描述）
_chars 字段 = 直接取 scene_map.characters，不取 VLM
```

### 情绪锚定（解决 VLM 采样偏差）

VLM 只采 1/3 + 2/3 两个位置的关键帧，可能错过冲突画面。所以把 scene_map 的 mood 注入 prompt 作为约束：

```
角色=柳青、苏明玉  地点=车内  事件=柳青抱怨老蒙测试忠诚度  情绪基调: 愤怒
★ 情绪要求: 这是一场「愤怒」的戏，emotional_tone 和 intensity 必须反映这个情绪基调
```

**结果：** 情绪矛盾从 22 个降到 0。

### 关键帧采样策略

- 场景内取 **1/3 和 2/3 位置**的帧（不是首尾帧——首帧可能落在上一场景，尾帧可能错过高潮）
- 避免场景切换边界画面不稳

## VLM 的工程要点

### 1. 推理模型的 token 坑

MiMo `mimo-v2.5` 是推理模型：`reasoning_content` 占满 token，`content` 可能为空。

```python
raw = msg.get("content", "") or ""
if not raw.strip():
    raw = msg.get("reasoning_content", "") or ""  # fallback
```

并且 `max_tokens` 要给足（4000），否则推理过程把配额耗尽。

### 2. 抽帧与复用

- `fps=1` 抽帧（每 1 秒 1 帧），帧序号 = 秒数，方便溯源
- 已存在的帧目录**复用**，别强制重抽（并发 ffmpeg 会超时）

### 3. 结构化 JSON 输出

让 VLM 输出严格 JSON（景别/构图/机位/情绪/强度/光线/动作），解析时多层容错（正则提取 → 纯文本降级）。
