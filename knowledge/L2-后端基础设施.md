# L2: 后端基础设施

> VibeCut 的骨架 — HTTP 服务、数据库、流式协议、媒体处理

## 本层知识点

| 笔记 | 主题 | 难度 | 状态 |
|------|------|------|------|
| [[HTTP服务与SSE流式]] | http.server, REST API, SSE | 🟢 | ✅ |
| [[SQLite数据层设计]] | WAL模式, Schema设计, 线程安全 | 🟢 | ✅ |
| [[ffmpeg媒体处理]] | 视频转码, 音频提取, 代理生成 | 🟢 | ✅ |

## 为什么这层重要

这层是 VibeCut 能跑起来的骨架。没有这层，AI 模型只是独立脚本，无法被前端调用。

**关键是：这层用的全是标准库和系统工具，零额外依赖。**

## 与其他层的关系

```
L1 (Python/Shell) ──→ L2 (HTTP/SQLite/ffmpeg)
                         │
                         ├──→ L3 (AI基础层) — AI 模型通过 HTTP API 暴露
                         ├──→ L4 (RAG体系) — 搜索 API 端点在 HTTP 服务中
                         └──→ L6 (前端工程) — 前端通过 HTTP + SSE 与后端通信
```

## 学习建议

重点理解三个模式的底层原理，而不是框架用法：
1. **HTTP Server：** 请求→解析→路由→处理→响应，每个环节发生了什么
2. **SSE：** 为什么用 Event Stream 而不是轮询或 WebSocket
3. **SQLite WAL：** 为什么能支持并发读写
