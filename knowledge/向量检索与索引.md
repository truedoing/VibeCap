# 向量检索与索引

> 用 `np.dot` + `np.argsort` 做语义搜索 —— 不需要 Milvus，不需要 Pinecone，numpy 就够了。

## 是什么

**向量检索**是在一组向量中找到与查询向量最相似的那些。当你输入"苏大强在老宅翻存折"，系统把这句话编码为 768 维向量，然后在预先编码好的几万条视频片段向量中，找出夹角最小的 Top-K。

**为什么不用专门的向量数据库（Milvus / Pinecone / Qdrant）？**

| 向量数据库 | VibeCut 的 numpy 方案 |
|-----------|---------------------|
| 需要安装独立服务 | Python 标准库 + numpy |
| 网络调用延迟 | 内存内 `np.dot()` |
| 对 1 万-10 万条数据是杀鸡用牛刀 | 17 万条内 `np.dot` 毫秒级完成 |
| 适合多租户、高并发、元数据过滤 | 适合单机、单人、全量搜索 |

核心认知：**向量检索本质上就是一个矩阵乘法**。当数据量在可装入内存范围内时，numpy 的 dot product 是最快、最简单的方案。

## 关键概念

### 1. 矩阵乘法实现相似度计算

```
encoding_matrix: (N, 768)  ← N 个文档片段，每段 768 维
query_vector:    (768,)     ← 查询文本的编码

scores = np.dot(encoding_matrix, query_vector)  # (N,) 每条文档的相似度
top_k_idx = np.argsort(scores)[-K:][::-1]        # 得分最高的 K 个
```

为什么一个 `np.dot` 就够了？因为所有向量已经经过 L2 归一化（模长=1），此时向量点积 = 余弦相似度。数学上：

```
cos(a, b) = (a · b) / (|a| × |b|)
         = a · b          (当 |a| = |b| = 1 时)
```

### 2. mmap 零拷贝加载

```python
# 不加载到内存，直接从磁盘映射
semantic_emb = np.load("semantic_embeddings.npy", mmap_mode='r')

# 访问时操作系统自动按需分页读入
scores = np.dot(semantic_emb, query_vector)  # 只读取需要的页
```

传统的 `pickle.load()` 会把整个文件加载到内存。对于 46 集电视剧（可能 17 万条 x 768 维 = ~500MB），这不现实。`mmap_mode='r'` 让 numpy 直接从磁盘映射内存页，操作系统按需加载 —— 你只实际读取了计算时需要的那些内存页。

VibeCut 的双格式保存策略：
- **pickle (semantic_index.pkl)**：兼容旧版，一次性加载
- **npy + json (semantic_embeddings.npy + semantic_metas.json)**：mmap 零拷贝，生产用

`cli/build_index.py` 构建时同时保存两种格式；`routers/_lifespan.py` startup() 加载时优先用 npy (mmap)，找不到才用 pickle。

### 3. 阈值过滤

```python
for i in top:
    if scores[i] <= 0.25: continue  # 相似度太低，丢弃
    ...
```

阈值不是拍脑袋定的。经过实际测试：
- 口播（interview）：阈值 0.30 —— 数据量小（几百条），放松门槛
- 电视剧（drama）：阈值 0.25 —— 数据量大（数万条），适度过滤噪音

低于阈值的相似度得分意味着"模型认为查询和文档基本不相关"。

### 4. 去重

```python
k = f"{m['ep']}_{m['start']:.0f}"
if k not in results or r["score"] > results[k]["score"]:
    results[k] = r
```

同一个时间段可能出现多条索引（例如 VLM 描述 + ASR 转写 + 字幕都指向同一秒），去重键 `ep_start` 确保结果中每个时间位置只出现一次，取最高分。

### 5. 启动注入全局搜索状态

```python
# routers/_lifespan.py 的 startup() 里，把索引状态注入 handlers.search
import handlers.search as hs
hs.semantic_emb = semantic_emb
hs.semantic_metas = semantic_metas
hs.asr_data = asr_data
hs.vlm_data = vlm_data
hs.interview_asr = interview_asr
```

设计要点：`routers/_lifespan.py` 在启动时加载索引并注入 `handlers/search.py` 的模块级全局，加载逻辑与搜索逻辑解耦；`handlers/storyboard.py` 等业务层直接调用搜索函数。

## 动手实验

1. **从零做一个向量检索**

```python
import numpy as np

# 模拟编码（实际中这步用 BGE 模型）
np.random.seed(42)
docs = np.random.randn(10000, 768).astype(np.float32)
# 归一化
docs = docs / np.linalg.norm(docs, axis=1, keepdims=True)

# 编码查询
query = np.random.randn(768).astype(np.float32)
query = query / np.linalg.norm(query)

# 检索
scores = np.dot(docs, query)
top5_idx = np.argsort(scores)[-5:][::-1]
print(f"Top 5 scores: {scores[top5_idx]}")
```

2. **对比 mmap vs pickle 加载速度**

```python
import time, numpy as np

# 假设已有 semantic_embeddings.npy
t0 = time.time()
emb1 = np.load("semantic_embeddings.npy", mmap_mode='r')
print(f"mmap: {time.time() - t0:.3f}s, 内存: {emb1.nbytes/1024/1024:.0f}MB")

t0 = time.time()
emb2 = np.load("semantic_embeddings.npy")
print(f"full load: {time.time() - t0:.3f}s, shape: {emb2.shape}")
```
