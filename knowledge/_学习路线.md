# 学习路线

> 从大二基础到 AI Agent 开发者的推荐路径

## 起点假设

- 掌握一门编程语言（Python 或 JavaScript 均可）
- 了解 HTTP 协议的基本概念（GET/POST、请求/响应）
- 用过 Git 做版本管理
- 写过简单的命令行程序或网页

**不需要：** AI/ML 背景、深度学习框架经验、视频编辑经验。

---

## 阶段一：地基 (2-3 周)

**目标：** 理解 VibeCut 怎么跑起来的

```
Week 1-2: 后端基础
  ├── Python 基础 → 看 [[Python基础]]（会一门语言就能上手，够用就行）
  ├── Python 进阶 → 看 [[Python-标准库与并发]]
  │   - threading, subprocess, pathlib
  │   - http.server 是怎么工作的
  │   - json/re 处理数据
  ├── SQLite → 看 [[SQLite数据层设计]]
  │   - 建表、查询、WAL 模式
  │   - 为什么不用 MySQL/PostgreSQL
  └── HTTP 与 SSE → 看 [[HTTP服务与SSE流式]]
      - REST API 设计
      - Server-Sent Events 原理
      - 为什么用 SSE 而不是 WebSocket

Week 3: 前端基础
  ├── JavaScript 模块化 → 看 [[JavaScript与React生态]]
  ├── React 组件化思维 → 看 [[React与Vite]]
  └── Vite 构建工具
```

**实践项目：** 用 `http.server` 写一个带 API 的小服务，前端调通。

**对应 VibeCut 代码：** `vibecut-server/main.py` + `routers/`, `vibecut-web/src/`

---

## 阶段二：AI 入门 (3-4 周)

**目标：** 理解 VibeCut 的"智能"部分怎么来的

```
Week 4-5: 文本与向量
  ├── Embedding 概念 → 看 [[文本嵌入与语义向量]]
  │   - 为什么文本能变成数字
  │   - BGE 模型是什么
  │   - sentence-transformers 怎么用
  ├── 向量检索 → 看 [[向量检索与索引]]
  │   - 余弦相似度
  │   - 为什么用 numpy 而不是向量数据库
  └── 动手: 用 BGE 给自己写一个本地语义搜索

Week 6-7: LLM 调用
  ├── LLM 基础 → 看 [[大语言模型LLM]]
  │   - System Prompt vs User Message
  │   - Temperature, Max Tokens
  │   - JSON Mode 结构化输出
  ├── API 调用模式 → 看 [[LLM调用与工具使用]]
  │   - OpenAI 兼容 API
  │   - 流式 vs 非流式
  │   - 重试与错误处理
  └── 动手: 用 DeepSeek API 写一个 prompt 调优实验
```

**实践项目：** 做一个"输入句子，找到 ASR 素材中最相似的句子"的小工具。

**对应 VibeCut 代码：** `cli/build_index.py`, `lib/llm.py`（统一 LLM 调用）

---

## 阶段三：RAG 深入 (2-3 周)

**目标：** 理解检索增强生成的全貌

```
Week 8-9: RAG 核心
  ├── RAG 是什么 → 看 [[RAG核心概念]]
  ├── Chunking 策略 → 看 [[文本切分与Chunking]]
  │   - 固定窗口 vs 语义切分 vs 说话人边界
  ├── 检索模式 → 看 [[混合搜索策略]]
  │   - 向量 vs 关键词 vs 混合
  │   - 重排序 (Reranker)
  └── 动手: 对比不同 chunking 策略对检索质量的影响

Week 10: RAG 框架
  ├── LangChain RAG vs LlamaIndex → 看 [[RAG核心概念]]
  └── 为什么 VibeCut 自研 BGE 方案 → 看 [[BGE索引实战]]
```

**实践项目：** 用 LangChain 的 create_retrieval_chain 搭一个文档问答 demo，和 VibeCut 的 BGE 自研方案对比。

**对应 VibeCut 代码：** `cli/build_index.py`, `handlers/search.py`（语义 + 关键词 + 混合搜索）

---

## 阶段四：Agent 开发 (3-4 周) 🔄 规划中

**目标：** 从"AI 辅助工具"到"AI Agent 自主执行"

```
Week 11-12: Agent 基础
  ├── Agent 概念 → 看 [[Agent核心概念]]
  │   - Tool Use / Planning / Reflection
  │   - Agent Loop (Observe → Think → Act)
  ├── LangGraph → 看 [[LangGraph框架]]
  │   - StateGraph, Node, Edge
  │   - ConditionalEdge (条件路由)
  │   - Checkpointer (状态持久化)
  └── 动手: 用 LangGraph 写一个 Todo Agent

Week 13-14: Agent 进阶
  ├── 工具定义 → 看 [[工具定义与MCP]]
  │   - @tool decorator
  │   - JSON Schema 自动生成
  │   - MCP 协议
  ├── 人机协作 → 看 [[人机协作HITL]]
  │   - interrupt / resume
  │   - 审批流设计
  ├── Agent 测试 → 看 [[Agent测试与评估]]
  │   - Harness 是什么、五部件
  │   - 确定性部分 pytest vs 概率性部分 harness
  │   - 评估边界与 ground truth 设计
  └── 动手: 把 VibeCut 的一个模块封装为 Tool
```

**实践项目：** 把 `handlers/pipeline.py` 的 run_pipeline 用 LangGraph 重写。

**对应 VibeCut 代码（规划）：** `vibecut-server/agent/`

---

## 阶段五：前沿探索 (持续)

**目标：** 站在 AI 应用开发的最前沿

```
├── Agentic RAG → 看 [[Agentic-RAG]]
│   - Agent 自主决定搜什么、搜几次
│   - 多轮搜索 + 结果反思
├── 多 Agent 协作 → 看 [[多Agent协作]]
│   - 不同剪辑风格对应不同 Agent
│   - Agent 间协商
├── Agent 自我学习 → 看 [[Agent自我学习]]
│   - 偏好学习
│   - 从反馈中改进
│   - 跨任务知识迁移
└── MCP 生态集成 → 看 [[工具定义与MCP]]
    - 社区工具复用
    - 工具市场
```

## 学习检查点

每个阶段完成后的自检问题：

| 阶段 | 自检问题 |
|------|---------|
| 地基 | 我能解释 VibeCut 后端收到一个 GET /search 请求后的完整处理流程吗？ |
| AI 入门 | 我能解释 "一句中文怎么变成 768 个数字，又怎么和其他句子比相似度" 吗？ |
| RAG 深入 | 我能说出 VibeCut 的 BGE 方案和 LangChain 标准 RAG 的三个关键区别吗？ |
| Agent | 我能画出 VibeCut Agent 的 StateGraph 并解释每个 Node 的职责吗？ |
| Agent | 我能说出「确定性测试」和「Harness 评估」分别测什么吗？ |
| 前沿 | 我能说出 "Agentic RAG" 和 "Naive RAG" 在搜索策略上的本质区别吗？ |
