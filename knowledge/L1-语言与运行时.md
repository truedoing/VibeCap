# L1: 语言与运行时

> 支撑 VibeCut 运行的编程语言、工具链和运行时环境

## 本层知识点

| 笔记                     | 主题                                          | 难度  |
| ---------------------- | ------------------------------------------- | --- |
| [[Python基础]]            | 类型/容器/函数/类/模块/异常（够用就行）               | 🟢  |
| [[Python-数据处理]]        | json, re, 文本清洗, numpy                       | 🟢  |
| [[Python-标准库与并发]]      | pathlib, subprocess, threading, http.server, async | 🟢  |
| [[JavaScript与React生态]] | ES Module, JSX, npm, Vite                   | 🟢  |
| [[Shell与ffmpeg工具链]]    | Bash 脚本, ffmpeg 视频处理                        | 🟢  |

## 为什么从这里开始

VibeCut 的代码大量使用 Python 标准库和基础工具。理解这些不是"学框架"，而是"学怎么不依赖框架也能做事"。

**关键原则：** VibeCut 的底层能力尽量用标准库实现（pathlib/subprocess/threading/sqlite3），HTTP 层用 FastAPI——先理解底层机制，再用框架提速。

## 与上层的关系

```
L1 语言与运行时
  │
  ├── Python 标准库 ──→ [[L2-后端基础设施]] (HTTP服务/SQLite)
  │                   ──→ [[L3-AI基础层]] (sentence-transformers/numpy调用)
  │
  ├── JavaScript/React ──→ [[L6-前端工程]] (UI组件/状态管理)
  │
  └── ffmpeg/Shell ──→ [[L2-后端基础设施]] (视频处理/代理生成)
```

## 学习建议

如果已掌握 Python 和 JavaScript 基础语法，本层重点学：
1. **Python 标准库** 能做多少事（http.server、sqlite3、threading 都是标准库）
2. **ffmpeg** 的命令行接口（不是库，是独立进程调用）
3. **Vite** 的构建理念（为什么比 Webpack 快）
