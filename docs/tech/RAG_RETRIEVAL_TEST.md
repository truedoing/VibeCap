# RAG 闭环测试报告（最终版）

> 测试案例：**苏明成人物线:从妈宝到守护者**
> 日期：2026-08-13 · 目标时长 240s · LLM=DeepSeek

## 一、三种模式定义

| 模式 | 检索键 | 故事师读什么 | 用户是否指定集 |
|---|---|---|---|
| **baseline** | 无（全量内联） | 46 集概要全塞 | 指定了但被无视 |
| **shallow** | 剧集号（元数据键） | 只读指定 5 集概要 | 指定 `[1,21,35,39,41]` |
| **deep** | 选题语义（LLM 反推） | 只读反推 ~8 集概要 | **不指定**，只给选题 |

> 「人工指定 5 集」只是用于对比的旧模式基准。新模式（deep）本就不需要用户指定集。

## 二、结果总览

| 指标 | baseline | shallow | deep（最终 V5） |
|---|---|---|---|
| 故事师读的集数 | 46 | 5 | 8（LLM 反推） |
| 故事师耗时 | 39s | 31s | 30s |
| 总耗时 | 94.1s | 82.7s | 79.1s |
| highlight_scenes 涉及集 | 11 集（跑偏到 13/24/40/42/44/46） | **5 集（精确）** | 8 集 |
| turning_points 涉及集 | 10 集（混入 9/13/20/24/31/40/44） | **5 集（精确）** | 8 集 |
| 产出 segments | 22 段 / 1647 字 | 20 段 / 1624 字 | 23 段 / 1532 字 |
| 校验修正 | 0 处 | 3 处 | 0 处 |

## 三、核心结论

### 1. shallow 是"纯 bug 修复级"的胜利，当前最优解

baseline 虽然指定了 `[1,21,35,39,41]`，但故事师无视它、读了 46 集，产出跑到 11 个集。shallow 让 `focus_episodes` 真正生效后，产出**精确收窄到 5 集**。

- **0 额外 LLM 成本、精确命中、改动最小**（`_load_all_synopses` 加一个参数过滤）
- 这是整个 RAG 闭环的地基——打通了"按集喂"的通路

### 2. deep 的检索键，是"叙事弧线理解"——for 循环和 BGE 都不行

deep 检索键的演进，把"技术选型"这个抽象问题变成了实测数据：

| 检索键 | 技术 | 命中人工指定 5 集 |
|---|---|---|
| 人名/频率 | for 循环统计 | 0/5 |
| 概要相似 | BGE 向量 | 1/5 |
| 叙事弧线 + 情绪签名（V3） | LLM + 旧纯文本 | 4/5 |
| 叙事弧线 + 结构化 synopsis（V4） | LLM + 取前 200 字 | 2/5 |
| **叙事弧线 + 字段级检索（V5）** | LLM + character_arcs 字段 | **3/5** |

**结论**：深层 RAG 的检索键需要 LLM 级语义（叙事弧线理解），但**检索的"喂入方式"必须跟着数据形态走**。

### 3. 最有价值的一课：数据升级了，检索必须跟着升级

V4 → V5 这段演进，是本次测试最有教学价值的发现：

- **V4 踩坑**：synopsis 升级成结构化后，检索代码还在用"取 to_text() 前 200 字"，把最关键的人物弧线字段截掉了——**数据更好，检索反而从 4/5 掉到 2/5**。
- **V5 修复**：改成字段级检索（直接喂 `character_arcs` + `key_conflicts`），命中 EP39，回到 3/5。

> **结构化数据的字段，是"给检索用的钥匙"。数据升级成结构化，检索就不该再"取全文前 N 字"，而该"直接命中目标字段"。**

### 4. deep 的 3/5，不是失败，是"数据在纠正人工标注"

字段级检索后，剩下的"漏集"真相浮现——**人工指定的关键集，和数据里的真实弧线本身就不一致**：

| 集 | 数据里的苏明成弧线 | 人工标注 |
|---|---|---|
| EP35 | 投资受骗→被开除（**与舅舅对立**，非与苏明玉） | 标了"关键" |
| EP41 | 冲动阻婚→情绪失控（**关系紧张，是低谷非守护**） | 标了"守护终点" |
| EP37 | 卖房还债→公开道歉（**关系缓和**） | 没标 |
| EP45 | 主动道歉→赴非洲前和解（**真正的和解终点**） | 没标 |

LLM 反推的 `[1,9,21,32,37,39,44,45]` 覆盖了苏明成**真实弧线**的大部分节点（21 入狱·冰点 → 32 离婚·谷底 → 37 卖房道歉 → 39 打架·关系改善 → 44/45 和解），**反而比人工标注更贴合"从妈宝到守护者"的真实脉络**。

> 结构化 synopsis 升级的真正价值，是把"人物真实弧线"精确暴露出来，让检索结果比"人工凭记忆标注"更准确。

## 四、三模式最终定位

| 模式 | 定位 | 状态 |
|---|---|---|
| **shallow** | 用户已知关键集时，精确降噪 | ✅ 生产可用（0 额外成本） |
| **deep** | 用户不指定集，自动反推弧线节点 | ✅ 验证可行，字段级检索是正确形态 |
| baseline | 旧实现（46 集全塞） | ❌ 已被 shallow 取代 |
