# 账号画像：用户画像的分层与配置

> 状态：设计文档 · 2026-08-14
> 归属：六站生命周期「⑥ 交付与运营」的起点 + 「① 项目」的输入约束

## 核心问题：用户画像挂在哪一层？

讨论"目标用户研究是谁做的"，暴露出一个层级混淆：影视剧公开发行是**制片人定受众**，但自媒体解说是**账号主理人定受众**。

**关键区别**：

| | 影视剧公开发行 | 自媒体解说 |
|---|---|---|
| 谁定受众 | 制片 + 出品方 | **账号主理人**（你就是出品方+发行方） |
| 受众从哪来 | 全市场 | 账号粉丝画像（平台后台数据） |
| 画像在哪 | 市场调研报告 | **账号定位（配置 + 平台数据）** |

## 三级画像（从上到下逐层细化）

用户画像不是单一对象，是**约束链**：

| 层级 | 画像 | 挂在哪 | 谁定 | 载体 |
|---|---|---|---|---|
| **账号级**（最高） | 我的号是什么、给谁看、要什么 | ⑥ 自媒体运营层 | 账号主理人 | **配置（可改）** |
| **选题级** | 这个选题对准账号里的哪群细分 | ① 项目/选题层 | 制片 Agent | 读账号画像后评判 |
| **单视频级** | 这条视频怎么勾住具体的"他" | ②~④ 生成层 | 文案师 | 继承账号画像后表达 |

## 核心判断

1. **账号级画像 = 配置，不是 Agent**。它是慢变、低频的，不该每次生成都跑一个 Agent。
2. **制片 Agent 和文案师都从它继承，不各自写死**。换账号（如"剧粉向"）时，剥层策略跟着变。

## 账号画像字段（从解说法论提炼）

```json
{
  "account": {
    "positioning": "影视解说 · 人物线/情感/冲突向",
    "core_audience": "解读消费者（非剧粉）",
    "audience_want": "认知增量 —— 看到观众自己看不到的东西",
    "topic_types": ["人物性格型", "事件策略型", "反差打脸型"],
    "framework_ratio": "常规70% + 框架30%（MBTI/依恋理论/博弈论）"
  }
}
```

- `positioning`：账号定位（一句话）
- `core_audience`：核心受众（谁）
- `audience_want`：受众要什么（价值主张，这是"剥层"的依据）
- `topic_types`：允许的选题类型（制片 Agent 的约束）
- `framework_ratio`：框架型选题占比

## 演进：从硬编码到配置

| 之前 | 之后 |
|---|---|
| `producer_agent` 默认参数写死"影视解说·人物线/情感/冲突向" | 从项目 json 的 `account` 读 |
| 文案师 prompt 写死"解读消费者" | 从 `account.audience_want` 注入 |
| 换账号要改代码 | 改配置文件即可 |

## 在六站地图的位置

```
⑥ 交付与运营：账号定位(画像定义) → 发布 → 播放数据 → 反哺选题
   ↑ 这是运营层的起点，之前漏了
```

账号画像是⑥运营层的**前置定义**——先定画像，才有后续的发布、数据、反哺。它同时作为①项目层（制片选题）的**输入约束**。
