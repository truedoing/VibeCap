# 选题推荐：制片 Agent（决策层）设计

> 状态：已实现 · 2026-08-13
> 归属：四台流水线第一台「项目 · 制片 · 选项目」

## 核心设计：生成与决策分离

选题推荐不是"一个 Agent 从头做到尾"，而是**两个层级、三种角色**：

```
【生成层】产出候选选题
  统计挖掘（cli/topic_recommend.py）── 数据向候选
  故事师（story_master_agent）─────── 叙事向候选
        │
        ▼
【决策层】评判 + 排序 + 拍板
  制片 Agent（producer_agent）── 首推选题 + 推荐理由
        │
        ▼
  首推选题 → cli/generate_drama.py → 生成脚本 → E2E 度量
```

## 为什么制片 Agent 必须是"决策层"，不是"生成层"

**职责分离的关键**：生成和决策是两种不同的智能。

| 层级 | 角色 | 干什么 | 技术 |
|---|---|---|---|
| 生成层 | 统计 | 数据向候选（冲突密度/关系强度/情绪弧线） | 程序（确定性） |
| 生成层 | 故事师 | 叙事向候选（人物线/主题/事件，带 hook） | LLM 生成 |
| **决策层** | **制片** | 评判流量/差异化/钩子/匹配，排序，给理由 | LLM 判断 |

- **统计**能算出"EP22 冲突密度 100%"，但不能判断"这个选题值不值得做"。
- **故事师**能提出"苏明成救赎"，但不能排序"它和 EP21 窒息哪个更该做"。
- **制片**不做生成，只消费候选做决策——如果它自己去读 scene_map 生成选题，就变成了"第二个故事师"，职责重叠。

## 制片 Agent 的评判维度

| 维度 | 含义 |
|---|---|
| traffic（流量潜力） | 话题是否自带讨论度、共鸣、搜索热度 |
| differentiation（差异化） | 是否独特，不被同质化解说淹没 |
| hook（钩子强度） | 能否提炼 3 秒抓人的开场观点 |
| fit（账号匹配） | 是否契合账号定位（影视解说 · 人物线/情感/冲突向） |

输出：`ranked`（排序 + 每维分 + 推荐理由）+ `top_pick`（首推）+ `strategy_note`（整体策略）。

## 一个真实的坑：证据公平性

第一次跑制片 Agent，发现**叙事向选题被系统性降级**——因为它把"数据向选题的硬数据（冲突密度 100%）"当成强证据，而把"叙事向选题的 hook"当成弱证据，导致故事师的 5 个选题全被挤出 Top 15。

修复：在 prompt 里明确"两种来源证据性质不同但价值等同，叙事向的 hook 本身就是它的数据"。修复后叙事向选题回到推荐榜（"苏明成与苏明玉"17分、"苏大强与苏明玉"16分）。

**教训**：多源候选喂给决策 Agent 时，**证据强度必须对等**，否则 Agent 会系统性偏向"有硬数据"的一方。

## 实战产出质量（2026-08-13）

- 首推：`EP22 全剧最窒息的一集`（冲突密度 100%）
- 策略 note：`优先推冲突密度最高的单集制造极致情感冲击，搭配同框最多的父子关系线形成互补，兼顾单点爆发与关系深度` —— 这是真实的制片思维，不是套话
- 排序理由结合数据 + 叙事："苏明成与苏明玉 兄妹暴力冲突名场面多，但同题材解说较多，差异化稍弱"
