# 解说与原声编排方法论

> 状态：方法论沉淀 · 2026-08-14
> 归属：编剧台「解说脚本生成」的编排层约束
> 与 `STORY_ARC.md` 互补：STORY_ARC 管"选什么弧"，本文件管"弧选定后，解说和原声怎么编排"

## 核心定位

**解说是主线，原声是武器。** 每一段原声都要"干活"——它不是用来复述剧情，而是用来支撑解说的论证。

- 解说 = 论证（提出判断、拆解逻辑、给出洞察）
- 原声 = 呈堂证供（证明解说说的对）或情绪炸弹（文字扛不住的让原声扛）

## 原声的六种功能

每条原声必须承担以下至少一种功能，否则不放：

| 功能 | 定义 | 判断标准 |
|---|---|---|
| 举证 | 解说刚抛出判断，用原声证明"确实如此" | 删掉这段原声，观众会觉得"口说无凭" |
| 引爆 | 文字描述不了的情绪冲击，让演员表演自己说话 | 这段戏观众会截图发朋友圈 |
| 钉人 | 一句话浓缩角色本质，让观众对这个人"定型" | 只能用一段台词代表这个角色时，选这段 |
| 对冲 | 两段自相矛盾的原声并置，观众自己看出荒诞 | 把两段台词放一起，不需解说观众就能"打脸" |
| 喘息 | 连续分析后让观众从"理解模式"切到"感受模式" | 前面已有 200 字以上纯解说 |
| 锚定 | 开头钩住或结尾收束，用原声的情绪力做框架 | 位于脚本开头或结尾位置 |

## 两种编排模式

| 模式 | 结构 | 观众心理 | 适用位置 |
|---|---|---|---|
| **A 模式**（先解说后原声） | 解说抛判断 → 原声举证 | "解说说得对！被验证了！" | 主体段落，占主导（约 70%） |
| **B 模式**（先原声后解说） | 原声冲击 → 解说拆解 | "这是什么？为什么？原来如此！" | 开头引爆 + 中段反转，少量使用（约 30%） |

## 节奏规则（量化约束）

| 规则 | 数值 |
|---|---|
| 原声占总段落比例 | 25%-40% |
| 单段原声时长 | 5-15 秒（≤20 秒） |
| 连续纯解说上限 | ≤3 段（约 200 字），第 3 段后必须插原声 |
| 连续纯原声上限 | ≤2 段 |
| 一条脚本原声总数 | 4-8 段（800-1000 字脚本） |

## 位置规则

| 脚本位置 | 编排方式 | 说明 |
|---|---|---|
| 开头（前 3 段） | 蓄力解说 + 原声引爆（B 模式） | 2-3 句短解说攒好奇，用冲击力原声炸开 |
| 展开段 | A 模式为主：解说判断 → 原声举证 | 交替推进，解说抛观点后紧跟原声"盖章" |
| 核心洞察段 | 原声-解说-原声（三明治） | 最重要的分析段被原声夹住，增强说服力 |
| 高潮段 | 蓄力解说（2段）+ 原声爆点（A 模式） | 解说蓄力越足，原声爆发力越强 |
| 结尾 | 纯解说收束 | 升华段用解说自己的声音，不再用原声 |

## 特殊技巧

| 技巧 | 说明 |
|---|---|
| 原声复用 | 同一段台词可在开头和高潮各出现一次，第二次观众带着理解去看，感受升级 |
| 对冲编排 | 角色A的台词 → 短解说 → 角色A自相矛盾的台词，让观众自己"打脸" |

## 原声选择的硬性约束

| 约束 | 说明 |
|---|---|
| 独立可懂 | 选的片段不能让观众问"这谁啊？""为什么？" |
| 名场面优先 | 同一论证点有多段素材时，优先选观众有记忆的场面 |
| 服务于论证 | 不能因为"这段戏好"就放——必须服务于解说的逻辑 |
| **台词真实（严禁编造）** | highlight_text 必须来自 ASR 真实台词，程序从场景时间窗提取，文案师不填 |

## 关键实现：原声台词程序化提取

**先场景后台词**（用户核心方法论）：文案师只选场景（scene_query 的 episode + time_range），台词由程序从该场景时间窗的 ASR 里自动提取。

- 为什么：文案师"为了有原声而编台词"（9 条里曾 5 条编造），prompt"严禁编造"无效，因为没从机制上强制。
- 怎么做：Phase 4 里 `_pick_line_from_window(ep, time_range, asr_texts)` 从 ASR 时间窗挑最有冲击力的真实台词，填 highlight_text。
- 效果：0 编造（6/6 全部真实），场景选对台词自然关联出来。
