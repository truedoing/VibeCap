# 口播剪辑策略与算法

> 从引导式聊天素材中提取精华，生成短视频剪辑脚本。
> 持续优化中，每次实践后更新。

---

## 一、核心认知

### 口播素材的本质

引导式聊天 ≠ 即兴演讲。素材中包含两种声音：

| 层级 | 特征 | 用途 |
|---|---|---|
| **内容层** | 知识/经验/观点的表达 | 正片素材 |
| **元讨论层** | 商量怎么讲、评价讲得好不好、重新组织语言 | 剪辑师参考，不入正片 |

### 核心原则

> **正片不是从头剪到尾，而是从对话中"捞出"那些正式讲述的瞬间，按叙事逻辑重新排列。**

## 二、音频层：正式 Take 识别

### 2.1 原理

引导式聊天中，被采访者有两种发声模式：

| 模式 | 音量 (RMS) | 流畅度 | 语速 | 用途 |
|---|---|---|---|---|
| **讨论闲聊** | < -19 dB | 有磕巴、填充词 | 不均匀 | 不入正片 |
| **正式讲述** | > -18 dB | 流畅、无口头禅 | 均匀稳定 | ✅ 入正片 |

**阈值会因人而异，需要按素材校准。** 当前基准：中位数 + 1.5dB。

### 2.2 算法

```python
# 1. 逐段提取 RMS 音量
for segment in asr_segments:
    rms_db = ffmpeg_volumedetect(segment.start, segment.end)

# 2. 文本特征
has_filler = any(w in text for w in ['呃','嗯','就是说','那个','对吧','嘛','反正'])
has_meta   = any(w in text for w in ['怎么说','我应该','是不是','明白','好的','感觉','靠你了'])

# 3. 判定
threshold = median(rms_all) + 1.5  # dB
is_formal_take = (
    rms_db > threshold 
    and not has_filler 
    and not has_meta 
    and len(text) > 5
)
```

### 2.3 实现

```
工具: ffmpeg volumedetect 滤镜
命令: ffmpeg -ss {start} -t {dur} -i {video} -vn -af "volumedetect" -f null -
解析: stderr 中 grep "mean_volume: -XX.X dB"
```

### 2.4 经验参数

| 参数 | 当前值 | 说明 |
|---|---|---|
| 音量阈值 | 中位数 + 1.5 dB | 自适应，不硬编码 |
| 最小段长 | 5 字符 | 过滤"对""好"等单字回应 |
| 填充词表 | 10 个 | 需按说话人习惯扩充 |
| 元讨论词表 | 15 个 | 需按对话模式扩充 |

## 三、文本层：内容结构分析

### 3.1 LLM 分析 (DeepSeek)

输入：ASR 转写（带时间戳）
输出：结构化标注

```
每个句子标注:
  - importance: 1-5 (5=金句/hook)
  - is_golden: true/false
  - topic: 开场定调/案例/方法论/结构要点/收尾
  - redundancy: null/filler/repeat/tangent/greeting
  - suggested_trim: 建议删除的字词

整体分析:
  - title_suggestion: 标题建议
  - outline: 段落大纲 [{label, sentence_indices}]
```

### 3.2 对话结构模式

引导式聊天的典型节奏：

```
[0-10%]   选题试探: "这个值得讲吗？" "你讲讲那个"
[10-30%]  第一轮讲述: 正式输出核心内容，音量↑
[30-40%]  元讨论中断: "我不知道说清楚没有" "挺好的，但..."
[40-60%]  第二轮讲述: 补充细节、案例、个人经验
[60-80%]  碰撞金句: 两人一起琢磨标题级表达，音量波动大
[80-100%] 收尾串讲: "你串吧" 最后梳理
```

### 3.3 元讨论识别

关键信号词：
- **自我评价**: "说清楚没有"、"我觉得挺好的"、"可能再加一点"
- **方向讨论**: "你应该讲"、"能不能举个例子"、"前面还缺半句"
- **重述尝试**: "我应该这么说"、"教培老板千万别...不，一定要..."
- **交接信号**: "靠你了"、"你串吧"、"你看着怎么去串"

## 四、叙事层：脚本结构设计

### 4.1 短视频叙事弧线

```
HOOK+个人揭示 (8s) → 激将/挑衅 + 立即用"我就是..."建立可信度
EXCLUSIVE (3s)    → "从没对外分享过" 制造独家感
EMPATHY (5s)      → 共情观众，消除防御 ("爱学习但别乱学")
EVIDENCE (20s)    → 方法论+数据，四步展开
BRIDGE (3s)       → "每一条你都做不到" 制造焦虑
TURN (5s)         → "必须学" 情绪拐点
METHOD (10s)      → 降低门槛：怎么学
PERSONAL (10s)    → 亲身案例，数据收尾
INSIGHT (8s)      → 深层洞见，直给，不铺垫
```

### 4.2 开头策略

| 策略 | 示例 | 效果 |
|---|---|---|
| 激将+个人揭示 | "新东方你学不来 → 对对我就是学了三成" | 挑衅激起好奇心 → 立刻用亲身经历建立可信度 |
| 价值承诺 | "只学三成，就能翻倍" | 温和伸手，适合干货型 |
| 痛点直击 | "为什么你的转化率做不到80%" | 精准打击目标受众 |

**原则：开头两句话完成"挑衅→信任"的转换。** 第一句让人停下来，第二句让人相信你有资格讲。

**新增发现（来自成片对比）：**
- "激将+个人揭示"的组合优于纯价值承诺。单纯说"你一定要学"缺少张力。
- "从没对外分享过" → 一句话制造独家感。这是建议文案完全遗漏的情绪按钮。

### 4.3 收尾策略

不要重复开头。用不同维度收尾：

| 开头 (WHAT) | 收尾 (WHY/HOW) |
|---|---|
| "只学三成就能翻倍" | "因为拉开差距的是人才，不是流程" |
| 给承诺 | 给洞见 |

**新增发现：结尾直给洞察即可，不需要铺垫对比。** 成片删掉了"我们以为是流程好、SOP好"的铺垫，直接"拉开差距的就是人才"，更有力。

### 4.4 Hook 重复策略

短视频需要锚定记忆。**核心金句至少出现 3 次：**
- 第 1 次：开头（配合个人揭示）
- 第 2 次：中间（方法论展开后再次锚定）
- 第 3 次：收尾前（最后强化记忆）

成片中"三成/翻倍"出现 4 次，建议文案只有 2 次，差异显著。

### 4.5 共情层

**在方法论之前插入共情句。** 让观众感受到"你懂我"，而不是"你在教育我"。

| 类型 | 示例 |
|---|---|
| 理解焦虑 | "教培校长特别爱学习，但不要乱学" |
| 承认困难 | "听起来每一条你都做不到" |
| 降低门槛 | "我没有她那个实力，但我做我能做的" |

### 4.6 个人案例的位置

**先建立信任，再讲方法论。** 建议文案把个人案例放在四步之后，但成片把"对对我就是学了三成"放在开头。短视频逻辑：先用 3 秒证明你有资格，再用 30 秒讲方法论。

### 4.7 分段粒度

抖音 60-90s 快节奏：
- **15-25 段**，每段 raw 1-15s → cut 后 1-5s
- 每段只承载**一个信息点**
- 数字/金句独立成段（2-3s），不和其他内容合并
- 情绪拐点孤句成段（"必须学"）
- 自然停顿词（"嗯""啊"）保留，作为呼吸点

## 五、质检标准：AI 审核规则

> 来源：视频精彩标准 + 成片对标
> 编剧台导出前自动执行，不通过的项标红/标黄

### 5.1 四道及格线

| # | 标准 | 检测方法 | 不通过动作 |
|---|---|---|---|
| 1 | **一件事讲清楚** | 所有 segment 的 topic 是否指向同一主题（最大 topic 占比 > 60%） | 🔴 标红：主题分散 |
| 2 | **好开头** | S0 narrative_role ∈ {hook_tension, hook_promise}，importance ≥ 4 | 🟡 标黄：开头弱 |
| 3 | **亮眼标题** | 标题命中五类特征之一（具体/冲突/故事/反认知/借势） | 🟡 标黄：标题平 |
| 4 | **节奏明快** | 相邻 segment 语义相似度 < 70%，同义句自动标记 | 🟡 标黄：有冗余 |

### 5.2 标题特征检测

```python
标题特征 = {
    "具体":    包含数字/地名/人名/机构名,
    "冲突":    包含对比词(但/却/反而/vs/差距/学不来),
    "故事":    包含人称代词 + 动作动词(给/去/做/带/拆),
    "反认知":  包含否定词 + 常识性内容(不用/从没/居然),
    "借势":    包含知名品牌/人物/概念(新东方/985/百万),
}
```

### 5.3 片段精彩度评分

| 维度 | 权重 | 检测方法 |
|---|---|---|
| 能量值 | 30% | 音频 RMS > 中位数 + 2dB |
| 信息密度 | 25% | 文本长度/时长 > 3字/秒 |
| 反常识度 | 25% | LLM 判断：这句话让人意外吗？ |
| 可标题化 | 20% | LLM 尝试起标题：能起出好标题=好素材 |

**用法**：编剧台左侧转写面板，每句标注精彩度分（0-100）。低于 40 分的默认折叠。

### 5.4 同义句去重

文档原则：*"相同意思的话，取一句最简练、情绪最饱满、冲突最激烈的"*

```
算法：
1. 相邻 5 句内，LLM 判断是否表达同一意思
2. 如同一意思 → 保留 importance 最高、字数最少的
3. 标记其他为 redundancy: "repeat_of_S{N}"
```

### 5.5 工作流强制：标题优先

文档强调：*"先起标题，再定开头，不要剪完最后起标题"*

编剧台流程调整为：

```
Step 1: AI 分析转写 → 建议3个标题方向
Step 2: 人确认/修改标题（必选一，不可跳过）
Step 3: 以标题为核心，AI 推荐开头 S0
Step 4: 人确认开头 → AI 展开剩余结构
Step 5: 质检审核（5.1 四道线）
Step 6: 导出
```

## 六、三步文案生成算法

> 核心原则：**脚本完善了，镜头才能完善，导出剪映才能贴合需求。**
> 不是机械切碎，而是根据文案逻辑结构进行混编剪辑。

### 6.1 算法总览

```
输入: 分类后的 ASR (content/meta/guide/filler 已标注)
输出: 完善的 segments.json (可直接导出剪映, 只需微调)

Step 1: 大结构 — 确定叙事骨架
Step 2: 组织语句 — 跨时间混编 + 删次级信息  
Step 3: 精细化 — 查漏补缺 + 必要时 AI 补写过渡句
```

### 6.2 Step 1: 大结构

**目标**: 确定视频的宏观叙事弧线。

**输入**: 标准化文案 (segmented.json) + 内容分析报告

**LLM 任务**:
```
你是一个短视频策划导演。给定采访的完整内容精华，设计一个60-90秒短视频的叙事结构。

要求:
1. 确定一个核心主题 (≤15字)
2. 设计5-8个叙事段落，每段标注:
   - narrative_role (见4.2)
   - 该段的核心论点 (一句话)
   - 该段大致需要多长时间 (秒)
3. 确保结构有起承转合:
   - 开头必须包含: 激将/反认知 + 个人揭示
   - 中段必须包含: 方法论/数据
   - 收尾必须包含: 深层洞察
4. 如果有"共情层"，放在方法论之前

输出 JSON:
{
  "topic": "核心主题",
  "sections": [
    {"role": "hook_tension", "point": "核心论点", "duration": 5},
    ...
  ]
}
```

**输出**: 结构骨架 — 5-8 段，每段有明确的叙事角色和时间预算。

### 6.3 Step 2: 组织语句（混编）

**目标**: 为每个结构段落，从完整 ASR 中选出最佳句子，允许跨时间混编。

**核心原则**:
- **可以跨时间**: 不按 ASR 时间顺序，按叙事逻辑选句
- **删次级信息**: 只保留支撑论点的核心句，删掉解释性/铺垫性内容  
- **同义取最优**: 同一意思说了多次的，只取最精炼的一句
- **保留口语气息**: "那必须学" > "我们必须学"

**输入**: Step 1 的结构 + 完整分类 ASR (467段, 带 layer/importance/timestamp)

**LLM 任务** (对每个 section 分别执行):
```
给定:
  1. 当前段落的叙事角色: {role}
  2. 核心论点: {point}
  3. 目标时长: ~{duration}秒
  4. 完整采访ASR (带时间戳和重要性评分)

任务:
  从完整ASR中选出最能支撑该段落论点的5-10句原话。
  - 可以跨时间选择（不按ASR顺序）
  - 每句标注 source_start / source_end
  - 优先选 importance≥4 的句子
  - 如果同一意思有多句表达，只选最好的那句
  - 选句要覆盖论点的不同维度，避免重复

输出 JSON:
{
  "section_index": 0,
  "selected": [
    {"text": "原话", "source_start": 63.0, "source_end": 67.0, "reason": "为什么选这句"},
    ...
  ]
}
```

**对每个 section 执行后，合并得到完整的句子清单。**

### 6.4 Step 3: 精细化

**目标**: 检查逻辑完整性，必要时 AI 补写过渡句。

**输入**: Step 2 产出的完整句子清单 (按叙事顺序排列)

**LLM 任务**:
```
你是一个短视频精编师。审核以下脚本，完成三件事:

1. 逻辑检查: 
   - 段落之间是否有断裂？是否需要过渡？
   - 是否有重要信息缺失？
   
2. 节奏检查:
   - 是否有连续3句以上都来自同一时间段的"堆砌感"？
   - 句子长度是否过于均匀（缺少变化）？

3. 补写过渡句 (仅在必要时):
   - 如果两个段落之间有逻辑跳跃，写一句15字以内的过渡句
   - 如果开头缺少个人揭示，补一句"我体感"式的揭示
   - 标注 source: "ai_generated" (表示需要AI补录或从其他素材找)
   - 每段最多补1句，整片最多补3句

输出 JSON:
{
  "checks": {
    "logic_gaps": ["段落X和Y之间缺少因果连接"],
    "rhythm_issues": ["第3-5句来自同一时间段"]
  },
  "bridges": [
    {"after_section": 2, "text": "AI补写的过渡句", "source": "ai_generated"}
  ],
  "final_segments": [
    {"text": "...", "source_start": 63.0, "source_end": 67.0, "topic": "...", "edit_type": "trim"},
    {"text": "...", "source_start": null, "source_end": null, "topic": "...", "edit_type": "ai_generated"}
  ]
}
```

**输出**: 完善的 segments.json，标注了哪些是原文、哪些是 AI 补写的。

### 6.5 混编示例

```
原ASR时间线:
  [63s] 新东方从来不用优秀老师上低价引流        → Section 1 (Hook)
  [812s] 教培老板一定要学新东方                  → Section 1 (Hook)  
  [815s] 大家都以为新东方学不来                  → Section 4 (Challenge)
  [116s] 全是到985211的学校去社招实现的           → Section 5 (Method)
  [169s] 就已经是800万了                         → Section 5 (Method)
  [422s] 我们必须学                              → Section 4 (Turn)
  [551s] 她的每一点我都在学                      → Section 7 (Case)
  [587s] 它从一千万到五千万只用了两年              → Section 7 (Case)
  [1062s] 拉开差距的就是人才                      → Section 8 (Insight)

混编后 (叙事顺序):
  Section 1: [63s] + [812s]                    ← 跨10分钟的两个时间点混编
  Section 4: [815s] + [422s]                    ← 跨6分钟混编
  Section 5: [116s] + [169s] + [261s] + [311s] ← 四步来自不同位置
  Section 7: [551s] + [587s]                    ← 案例混编
  Section 8: [1062s]                            ← 独立收尾
```

**关键: 不是顺序剪辑，是按叙事逻辑重组。** 同一段落可以混合来自完全不同时间点的句子。

### 6.6 与导出剪映的关系

```
脚本完善度 → 导出贴合度 → 剪映工作量

Step 1-3 产出的 segments.json:
  - 每句精确到 source_start/end (原文)
  - ai_generated 标记清晰 (需补录)
  - 段落之间逻辑连贯 (不需要大调整)
  - 次级信息已删除 (不需要再去冗余)

导出时:
  export_capcut.py 读取 segments.json
  → 原文句: 直接引用源视频时间戳
  → AI补写句: 生成静音clip, 标记人工配音
  → 段落间: 自动插入 0.3s 转场间隙
```

## 七、编辑节奏学（来自成片 SRT 分析）

> 成片 74s / 55条字幕 / 8段落。AI 建议的内容几乎全中，差距在"节奏编排"。

### 6.1 呼吸词策略

编辑保留了 7 个呼吸词（嗯/啊/对对），共 1.8s。它们不是废话，是节奏标记：

```
位置分布:
  3.5s  "对对" — 个人揭示前的过渡 (0.5s)
  13.1s "嗯"   — 转折后的停顿 (0.2s)
  20.0s "嗯"   — 方法论前的准备 (0.2s)
  30.3s "嗯"   — 第二步和第三步之间 (0.2s)
  34.3s "嗯"   — 第三步和第四步之间 (0.2s)
  51.3s "嗯"   — 过桥后的换气 (0.2s)
  63.7s "嗯"   — 案例前的呼吸 (0.2s)
```

**规律：每段之间必有一个呼吸点。** 0.2s 的"嗯"比 2s 的无声停顿更自然——它保留了说话人的节奏感。

### 6.2 金句独立成幕

```
"但只学三成就能翻倍" — 2.1s 独立字幕
"你只要学三成"       — 1.2s 独立字幕  
"你就可以翻倍了"     — 1.0s 独立字幕
```

**金句必须单独给时间，不能和其他内容挤在同一屏。** AI 生成时要标记哪些句是"金句级"，建议独立成段。

### 6.3 长句断开

编辑把长句切成短屏，每屏 1-2 秒：

```
AI建议: "全是到985211的学校去社招实现的"
成片:   "全是到985211的这样" (2.4s)
        "的学校去社招"       (1.5s)

AI建议: "第一人才选拔，全是到985、211的学校去校招实现的，人才质量一开始就拉开差距了"
成片:   "第一人才选拔"               (1.2s)
        "全是到985211的这样"          (2.4s)
        "的学校去社招"                (1.5s)
```

**规则：口语长句切成 2s 以内的字幕单元。**

### 6.4 Hook 重复模式

```
4次 Hook 出现:
  1.4s     "但只学三成就能翻倍"     ← 紧接激将,给出承诺
  4.0s     "我就是学了三成"         ← 个人身份锚定
  14.4s    "你只要学三成"           ← 方法论前再次锚定
  15.5s    "你就可以翻倍了"         ← 完整表达
```

**模式：开头(承诺)→个人(身份)→中间(锚定)→收尾(行动召唤)。** 4 次出现，每次功能不同。

### 6.5 口语气息

```
"那必须学"   而不是 "我们必须学"
"对对"       而不是删掉口吃
"嗯" "啊"    保留而不是剪切
```

AI 倾向于输出书面化的完整表达。真实口语的"那"、"对对"、"嗯"反而是信任感来源。

### 6.6 数字分布

成片只保留 3 个数字：800万(投入)、8万(奖金)、翻一倍(结果)。对应"投入→激励→产出"的叙事逻辑。不是数字越多越好——三个数字恰好覆盖一条因果链。

## 八、导出层：剪映草稿

### 5.1 核心设计

- **一个完整源文件** 作为素材（不切割成小文件）
- **纯时间引用**: `source_timerange` 指向源视频绝对时间
- 用户可自由拉长/缩短任何一段的入出点
- 视频轨自带音频 (`has_audio: true`)，不需要独立音轨

### 5.2 CapCut draft_info.json 关键结构

```json
{
  "materials": {
    "videos": [{"id": "...", "path": "源视频路径", "has_audio": true}],
    "audios": [{"type": "video_original_sound", "video_id": "..."}]
  },
  "tracks": [{
    "type": "video",
    "segments": [{
      "material_id": "...",
      "target_timerange": {"start": 0, "duration": 3000000},
      "source_timerange": {"start": 63000000, "duration": 5000000}
    }]
  }]
}
```

**关键：`source_timerange.start` 是源视频绝对时间（微秒），不是从 0 开始。**

### 5.3 音频注意事项

- 视频素材 `has_audio: true` 应在剪映中自动播放声音
- 如无声，检查 `draft_info.json` 是否完整（不是损坏的 JSON）
- `sound_channel_mappings` 保持 `type: "none"`

## 十、AI 分析校准

### 7.1 Prompt 设计要点

基于成片对标校准，prompt 必须包含：

```
1. 素材特征说明：引导式聊天的两层结构（内容层 vs 元讨论层）
2. 分层标注：speaker(guest/host) + layer(content/meta/guide)
3. 叙事角色：hook_tension/hook_promise/personal_reveal/empathy/evidence/bridge/turn/proof/insight
4. 金句识别：可重复锚定的 hook_candidates
5. 开头策略：tension_first 还是 promise_first
6. 特殊检测：共情句、独家揭示句
```
