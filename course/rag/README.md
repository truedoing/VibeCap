# RAG 模块：数据与知识站的核心交付物

> 属于课程地图 ②「数据与知识」站。回答：怎么把数据资产变成 AI 能检索、能背书的生成能力。

## 核心命题

**RAG = 先检索，再把检索结果喂给生成。** 价值不在"向量化"，在「**检索键**」的选择。

- RAG 的**定义**是行为性的（先检索→再生成），不含特定技术。
- 但它的**技术含量**全在检索键的选择上：语义键（相似度）还是身份键（精确匹配）。
- "不用 BGE 仍然是 RAG"——换掉的是检索实现方式，不是 RAG 本身。

## 一个贯穿全程的判断：数据表示决定检索方式

> **检索的难度，是知识表示质量的函数。** 数据表示得好，检索就退化成精确查询（甚至觉得"没含量"）；表示得差，才需要在查询时花大力气（向量检索、图构图）。

VibeCut 属于前者——scene_map 建得好，检索"看起来简单"。**这恰恰证明技术护城河在知识表示（场记Agent），不在检索。**

## 三层技术结构

按「数据形态 + 规模 + 查询类型」三个扳机，决定该用哪种检索技术：

| 层 | 技术 | 数据 | 触发扳机 | 状态 |
|---|---|---|---|---|
| **第一层**（适配现在） | 结构化查询 / for 循环 | scene_map 1511 场景 | 身份查询 + 小规模 | ✅ 真实数据 |
| **第二层**（真实非结构化） | BM25 + 向量 + rerank | ASR 38272 条 + BGE 29854 条 | 相似查询 + 非结构化 | ✅ 真实数据（BGE 已建好） |
| **第三层**（规模化扩展） | 图数据库 + Text2Cypher | 百万级节点 | 规模 + 多跳 | 🟡 模拟数据（未达规模） |

### 第一层：结构化查询 / for 循环

**为什么 for 循环是对的**：1511 条数据，全扫 10ms 出结果。为一个 for 循环上向量库/图数据库是**负资产**。

**关键一课《什么时候一个 for 循环就够》**——真正的技术判断力，是知道"什么时候 for 循环就够了"，而不是什么时候都上 Neo4j。

### 第二层：BM25 + 向量 + rerank（最主流的 RAG）

**关键反转**：以为要"模拟"的向量 RAG，其实 VibeCut **已经真造了一个**——29854 条 ASR 台词被 BGE 打成了向量，87MB npy 就在项目里。

> BGE 不是"没用"，是"用在了第一层的场景上，错配了"。它的正确归宿是第二层的自由问答。**同一个技术资产，放错层是垃圾，放对层是宝贝。**

适用场景：自由问答（"苏明玉为什么恨她妈"）——查询是相似、数据是非结构化（ASR 台词）。

### 第三层：图数据库 + Text2Cypher（唯一需模拟的）

**Text2Cypher = LLM 把自然语言翻译成 Cypher 图查询**。需要：① Neo4j 库 ② schema 设计 ③ LLM 翻译层。

**为什么现在不用**：你的节点规模没到百万，硬上 Neo4j 是负资产。这是唯一"还没发展到"的场景，用模拟数据是正当的。

**但 GraphRAG 的思想要用**：VibeCut 已经在数据管线阶段完成了它最贵的"构图"步（场记Agent），缺的只是"检索 + 摘要"。本质是**一个「图已建好、只差游走」的轻量版 GraphRAG**。

## 真实数据演示（今天跑通，可直接进课件）

### 1. 实体锚定（身份查询）—— 剧情查证核心

断言「苏明成在 EP21 暴打苏明玉被拘留」，程序做精确过滤（非相似度）：

```
EP21 中 characters ⊇ {苏明成, 苏明玉} 且 mood ∈ {愤怒,激烈,冲突}
```

命中：`[240s-330s] 苏明成和苏明玉发生激烈争吵，苏明成动手打苏明玉，苏明玉被打倒在地 | mood=愤怒`

→ 命中了 = 有剧谱背书；没命中 = 张冠李戴警告。

### 2. 多跳遍历（图上游走）—— 以「苏明成」为起点

- **Hop1**（实体→场景）：苏明成出现在 569 / 1511 个场景
- **Hop2**（场景→共现人物）：苏大强 301、朱丽 255、苏明玉 179 —— 自动提取人物关系网络
- **Hop3**（场景→情绪聚合）：愤怒 83、激烈 64、紧张 69 —— 情绪弧线素材

### 3. 跨集问答 —— 用遍历回答真实问题

问「苏明玉和苏明成的关系何时开始缓和？」，按集聚合两人同场情绪，找到负转正拐点：**EP36→37、EP45→46**（对应"从妈宝到守护者"的弧线）。
