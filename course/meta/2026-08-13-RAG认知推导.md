# 元课程知识：RAG 认知推导全程（2026-08-13）

> 这不是一篇知识点，是「我们怎么一步步想到这个结论」的推导记录。
> 对课程而言，**推导过程比结论更有教学价值**——学员要学的不是"RAG 是什么"，而是"一个真实工程师如何从困惑走到判断"。

## 起点：一个真实的困惑

> "BGE 索引用途不大，可以砍。"

项目围绕《都挺好》积累了丰富数据，原本设想用 BGE 语义索引当 RAG 知识库，但发现用途不大，需要重新定位。

## 推导链条（每一步都踩实了）

### 第 1 步：BGE 与知识库不是一类东西

把「BGE」和「知识库」放一起比，本身是误会——它们是两个层级：

| | 是什么 | 本质 |
|---|---|---|
| BGE | 检索技术 | 把文本压成向量，算相似度（**降维**：字段边界被抹平） |
| scene_map | 数据资产 | 结构化事实本体（5 个字段可查询/校验/统计） |

**结论**：之前做的是"把百科全书撕成词条塞进搜索引擎"——结构丢了，只剩"语义像不像"。而影视解说创作者搜的是"具体的人/场景/台词"，不是"温馨氛围"。

### 第 2 步：RAG 不用 BGE，还叫 RAG 吗？

**认知分叉点**。拆开 RAG = Retrieval-Augmented-Generation：

- **向量化从来不是 RAG 的定义，只是实现 Retrieval 的其中一种手段。**
- 检索至少五种实现：向量(dense)、关键词(sparse)、结构化/图谱(Text2SQL)、函数调用、混合(hybrid)。

**关键洞察**：BGE 错配不是"RAG 没用"，是"RAG 里的 R，在 VibeCut 里应该是**结构化查询**，不该是**向量量化**"。

### 第 3 步：那我的 RAG 体现在哪个环节？

**扎心的诚实答案：现在一处完整的 RAG 都没有。**

| 环节 | 实际做的事 | 是 RAG 吗 |
|---|---|---|
| 故事师 | 46 集概要全量塞 prompt | ❌ 全量内联，没检索 |
| 文案师 | ±2 集 scene_map 全塞 | ❌ 全量内联，没检索 |
| 分镜匹配 | match_shot_query 结构化匹配 | 🟡 有检索，结果不回流生成 |
| 程序校验 | time_range 对齐后覆盖 | ❌ 后处理质检，非生成环节 |

**结论**：你以为在用 RAG，实际在用「长上下文 + 结构化匹配 + 后处理校验」——三者都不是 RAG。

### 第 4 步：RAG 是技术模式还是行为模式？

用户尖锐追问："不管什么检索方式，只要符合先检索再给 LLM 生成，就叫 RAG，这不是技术模式而是行为模式了？"

**结论**：对了一半。定义是行为性的，但这个行为模式**恰恰由一个技术限制催生**——模型上下文有限 + 会幻觉，所以只能"先筛相关的再喂"。所以准确说是"**由技术约束催生的行为模式**"。

真正的技术含量不在 R（检索是机械的），在两个决策上：**检索键是什么、注入点在哪**。

### 第 5 步：检索"没技术含量"，要不要上 GraphRAG / Text2Cypher？

这是关键转向——因为用户是在**为课程设计**考虑，不纯为应用。

**脚本比对 vs 技术**：一个 `for` 循环 + `if 苏明成 in characters` 确实谈不上技术含量。但：

> **真正的技术判断力，恰恰是知道"什么时候一个 for 循环就够了"**，而不是什么时候都上 Neo4j。

- 1511 条数据，for 循环 10ms 出结果，上图数据库是**负资产**。
- Text2Cypher 需要：Neo4j 库 + schema + LLM 翻译层——为 1511 条上这个，是"用框架重量掩盖不知道该用什么"。

### 第 6 步：那什么时候才用得上复杂技术？

推演出**三个扳机**（不是"规模大就自动上"，是三个独立扳机）：

| 扳机 | 含义 | 触发信号 |
|---|---|---|
| ① 规模 | 数据量越过扫描阈值 | for 循环从 10ms 变 10s |
| ② 查询类型 | 从身份变相似 | 从"苏明成在不在"变"找跟这段像的" |
| ③ 数据形态 | 从结构化变非结构化 | 从 scene_map 变"一堆没打标的文本" |

分阶段解锁：单剧身份查询(for) → 多剧平台(倒排索引) → 跨剧选题(向量·主题层) → 自由问答(BM25+向量+rerank) → 跨剧多跳(图库+Text2Cypher)。

**最有价值的一课**：BGE 不是"错了"，是"放错了层"——在场景检索层错配（要砍），在跨剧主题层才对（要捡回）。

### 第 7 步：课程分两层？还是要"广且高"？

用户的关键判断：技术当然适配软件，但学技术要考虑大众市场需求，不能软件用不上就不教。

**从"两层结构"升级到"广且高"**：

- 以前工程师是「专且深」——一个方向钻到底。
- AI 时代是「广且高」——全流程都懂 + 关键决策有高度。
- 融合产品经理、架构师、开发、运营，从产品设计一直到交付运营。

**最终落地**：课程按「Agent 产品端到端生命周期」分六站（①洞察与产品 ②数据与知识 ③模型层 ④Agent编排 ⑤产品工程 ⑥交付与运营），RAG 是 ② 站的核心模块。

## 反直觉洞察（课程钩子候选）

1. **数据表示决定检索方式** —— 技术含量在知识表示，不在检索。
2. **BGE 放错层是垃圾，放对层是宝贝** —— 同一个资产，层决定价值。
3. **什么时候一个 for 循环就够** —— 判断力比会用工具值钱。
4. **GraphRAG 思想要、框架不要** —— 已构图，只差游走。
5. **"没技术含量"是数据做得好的证据** —— 不是检索没做好。
